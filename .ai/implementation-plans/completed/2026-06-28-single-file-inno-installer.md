## Goal

Create a simple one-click, single-file Windows installer for the current application version using Inno Setup. The installer should install just this version, without auto-update behavior, and later installers with the same application identity should replace installed application files without deleting the user's existing app data.

## Non-Goals

- No automatic update checks or update feed.
- No code signing in this plan.
- No machine-wide/all-users installer.
- No backup/restore workflow.
- No change to runtime app-data, database, invoice PDF, OAuth token, or Settings behavior.

## Assumptions

- Inno Setup 6 is installed locally at `C:\Program Files (x86)\Inno Setup 6\ISCC.exe`.
- The installer targets Windows x64.
- The app is published self-contained so target users do not need to install .NET separately.
- The real publisher Google OAuth Desktop JSON remains local/ignored and is copied into the publish output only when present.
- User data remains under `%APPDATA%\visualtech.dk\MySmallBusinessLedger`.

## Current Problem / Current State

The app can be run from developer build output, but there is no single-file setup package for a non-technical Windows user. The app already keeps data under `%APPDATA%`, which is appropriate for preserving data across installer replacement.

## Desired End State

- Running one repository script produces `artifacts\installer\MySmallBusinessLedger-1.20.0-Setup.exe`.
- The setup installs per-user under `{localappdata}\Programs\MySmallBusinessLedger`.
- The setup creates a Start menu shortcut and offers an optional desktop shortcut.
- The setup uses a stable Inno `AppId` so future installers replace prior installed application files.
- Install, upgrade, and uninstall do not delete `%APPDATA%\visualtech.dk\MySmallBusinessLedger`.
- Documentation explains how to build the installer and what it does/does not preserve.

## Behavior-Preserving Boundary

The following must remain unchanged unless this plan explicitly says otherwise:

- user-visible behavior: app workflows, menus, settings, Google sign-in, invoices, economy overview, and lesson behavior remain unchanged after launch.
- public APIs / CLI / UI contracts: no new app UI or command-line behavior.
- durable file formats / artifacts / logs / reports: existing SQLite, window-placement, grid-column-width, Google token, and invoice PDF artifacts remain unchanged.
- database schema / migrations / persistence behavior: no schema changes.
- security / trust boundaries: no new network behavior and no secrets committed.
- error handling / failure reporting: runtime startup warnings/errors remain unchanged.
- performance/resource characteristics: runtime app behavior unchanged; published app is self-contained and therefore larger on disk.

## Intentional Behavior Changes

- Add packaging/build artifacts and docs.
- Add a single-file installer artifact generated by script.
- Later installers with the same `AppId` may replace installed application files, while app data remains untouched.

## Risks And Mitigations

- Risk: installer removes user data during uninstall or upgrade.
  - Mitigation: do not add `[UninstallDelete]` entries for `%APPDATA%`; document user-data preservation; add tests that scan the installer script.
- Risk: later installers do not replace old app files cleanly.
  - Mitigation: use a stable Inno `AppId`, stable install directory, and same app name.
- Risk: target machine lacks .NET 10.
  - Mitigation: publish self-contained for `win-x64`.
- Risk: unsigned installer triggers SmartScreen warning.
  - Mitigation: document that code signing is not included yet.
- Risk: real Google OAuth client JSON is accidentally committed.
  - Mitigation: preserve existing ignored local config model; no change to source-control policy.

## Open Questions

None. User approved Inno Setup, single-file installer, no auto-updates, and replacement without user-data loss.

## Final User Test Instructions

Post-completion user test: mandatory.

Prerequisites/setup:

- Windows x64 workstation.
- Inno-built installer artifact at `artifacts\installer\MySmallBusinessLedger-1.20.0-Setup.exe`.
- If testing Google Calendar sign-in, the real publisher OAuth JSON must have been present before installer build so it is bundled into the installed app.

Exact user actions or commands:

1. Double-click `artifacts\installer\MySmallBusinessLedger-1.20.0-Setup.exe`.
2. Accept the installer prompts.
3. Leave or select the optional desktop shortcut checkbox.
4. Launch `My Small Business Ledger` from the Start menu or desktop shortcut.
5. Open `Application > About My Small Business Ledger` and confirm version `1.20`.
6. Open `Application > Settings` and confirm app data/database paths still point to `%APPDATA%\visualtech.dk\MySmallBusinessLedger`.
7. If testing replacement later, install a later installer with the same `AppId` and confirm existing settings/database remain.

Expected successful result:

- The app launches from the installed shortcut.
- The installer is a single `.exe` file.
- Existing app data remains available.

Expected failure/safety result, if relevant:

- If the unsigned installer triggers Windows SmartScreen, that is expected until code signing is added.
- Uninstalling the app should remove installed program files/shortcuts but leave `%APPDATA%\visualtech.dk\MySmallBusinessLedger` intact.

Where to inspect artifacts, reports, logs, database state, or UI state:

- Installer: `artifacts\installer\MySmallBusinessLedger-1.20.0-Setup.exe`
- Published files: `artifacts\publish\MySmallBusinessLedger\win-x64\`

- Installed app: `%LOCALAPPDATA%\Programs\MySmallBusinessLedger`

Cleanup/reset instructions:

- Uninstall from Windows Apps/Programs if desired.
- Delete generated repo-local `artifacts\` folders if no longer needed.
- Do not delete `%APPDATA%\visualtech.dk\MySmallBusinessLedger` unless intentionally resetting all local ledger data.
